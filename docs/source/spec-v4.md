## ★ 개발 착수용 요약 — 이 절을 최우선으로 적용한다

> **개발자/AI 에이전트에게:** 이 문서는 요구사항이 정리된 착수 지시서다. 사용자가 이미 확정한 사항을 다시 질문하지 않는다. 현장 정보(운영체제 버전·웨일 버전·실제 예제 파일)가 없어도 모의 데이터와 샘플 파일로 구현을 시작한다. 구현 불가능하거나 서비스 정책에 의존하는 기능은 지원하는 척하지 말고 `실험/부분 지원/미지원`으로 표시한다. 아래 최신 결정이 문서의 오래된 표현보다 우선한다.

### 즉시 유의할 핵심 제약

1. **PDF는 직접 재생할 수 있다. PPTX의 애니메이션·고급 효과·동영상·음원은 파서/렌더러의 실제 구현 범위에서만 지원된다.** 미지원 기능을 원본 수준으로 재생한다고 광고하지 않는다.
2. **`.ppt`와 한쇼 `.show`의 설치 없는 원본 재생은 기술 경로가 아직 확정되지 않았다.** 컨버터 또는 지원 가능한 오픈소스 파서를 실험하고 라이선스/오프라인 여부를 확인한다. 기술 실험 실패를 전체 개발 중단 사유로 삼지 않는다.
3. **캔바와 미리캔버스 링크는 프로그램을 통해 관리형 탭·창으로 연다.** 공개 API·웹 DOM·화면 제약상 전체 슬라이드 목록, 미리보기, 페이지 번호, 자동 넘김, 우클릭 편집을 모두 지원한다고 가정하지 않는다.
4. **발표 중 현재 자료의 오디오/영상과 슬라이드 전환은 다른 프로그램 활성화로 정지하면 안 된다.** 다만 브라우저가 실제로 숨김/최소화된 화면의 미디어·렌더링을 제한하는 조건은 따로 시험한다.
5. **브라우저에 임시 저장된 수정 데이터와 로컬 PC에 저장된 정식 편집 데이터는 다르다.** 확장 제거·브라우저 오류에 대한 완전한 복구는 사용자의 로컬 백업이 있어야 한다.
6. **다운로드 버튼은 실제 다운로드 성공을 확인해야 한다.** 브라우저 캐시에 결과물이 들어갔다고 '저장 완료'를 표시하지 않는다.

### 개발 진행 원칙

- 요구사항 → 최소 기능 구현 → 단위·통합 테스트 → 웨일 수동 검증 → 다음 단계로 진행한다.
- 먼저 **작동하는 수직 기능**(PDF 2개 전환 + 리모컨 + 임시 편집 + 로컬 내보내기)을 완성한다. 실제 PPTX 포맷 완전 재현을 기다리느라 기본 제품 구현을 멈추지 않는다.
- 실제 웨일이 설치되지 않은 환경에서 구현 중이라면 Chromium 기반 테스트와 모킹 테스트까지 만들고, **웨일 실기기 테스트 필요** 상태를 기록한다.
- 미검증 로컬·웹 API는 대체 경로를 마련한다. 기능이 없을 때는 오류 대신 안내 및 지원 가능한 작업을 제공한다.
- 사양 변경은 작은 단위로 관리하고, 소스코드를 공개할 가능성을 고려해 모든 서드파티 라이브러리·폰트·아이콘의 라이선스를 기록한다.

## 0. 핵심 요약 및 이번 버전에서 확정한 결정

### 0.1 제품 정의

**사용자가 PDF, PPT/PPTX, 한쇼 및 캔바·미리캔버스 발표 링크를 웨일 확장 프로그램을 거쳐 실행하고, 별도의 교사용 리모컨·미리보기 편집창에서 여러 발표 자료를 교차 관리하며, 발표 중에도 포커스와 무관하게 가능한 재생 기능을 유지하고, 빠른 글상자 수정·판서·타이머·발표자 노트 등을 이용하는 수업용 프레젠테이션 운영 시스템**이다.

기존 PowerPoint나 캔바 편집기를 전면 대체하려는 제품이 아니다. **발표 진행을 중단하지 않는 것, 다중 자료 전환, 발표 중 빠른 수정, 교사용 제어의 통합**에 집중한다.

### 0.2 확정 원칙

1. **웨일 확장 아이콘을 시작점으로 삼는다.** 빠른 실행 메뉴에서 로컬 파일과 온라인 발표 링크를 등록한다.
2. **교사용 제어 화면과 발표 화면은 분리한다.** 듀얼 모니터에서는 모니터 1에 리모컨·편집창, 모니터 2에 발표 창을 배치한다. 단일 모니터도 지원한다.
3. **여러 자료를 동시에 세션에 등록한다.** 자료를 바꿔도 각 자료의 마지막 슬라이드, 노트, 판서, 가리개, 수정 레이어와 재생 위치를 기억한다.
4. **다른 프로그램을 사용한다고 재생을 멈추지 않는다.** 발표 중인 자료에 대해 영상·음원·지원 애니메이션·자동 넘김·타이머가 창 포커스 이동과 독립적으로 진행되는 것을 목표로 한다. 단, 외부 웹 발표는 기술 검증 범위 내에서만 보장한다.
5. **발표 중인 화면뿐 아니라 비공개 미리보기의 다른 슬라이드도 수정한다.** 편집 대상으로 선택한 슬라이드와 청중에게 실제 표시되는 슬라이드는 각각 독립 상태이다.
6. **원본의 전면 편집은 추진하지 않는다.** 사용자 제작 단색 글상자·판서·가리개 등의 **오버레이(편집 레이어)**를 중심으로 빠른 수정을 지원한다.
7. **우클릭/길게 누르기로 빠른 글상자를 만든다.** 클릭 위치 색과 주변 단색 배경의 후보 중 선택하고, 드래그한 영역 안에 텍스트가 최대한 크게 표시되게 한다.
8. **최소·최대 글씨 크기, 기본 폰트 등은 사전 설정한다.** 검정 배경을 선택하면 기본 글자색은 흰색, 다른 일반 배경에서는 검정색이다. 사용자가 변경할 수 있다.
9. **종료 기본값은 '현재 자료 종료'이다.** 별도의 **전체 자료 일괄 종료** 명령을 제공한다.
10. **저장은 원본 불변·복사본 생성이 기본 원칙이다.** 수정 내용은 수업 세션에 남기고, 지원 가능한 형식의 복사본으로 내보낸다. 원본 자동 덮어쓰기를 제공하지 않는다.
11. **PDF·PPTX·한쇼와 웹 링크의 지원 수준을 구분한다.** 모든 자료가 같은 조작 버튼을 표시하더라도 실제 기술적으로 검증된 기능만 활성화한다.
12. **확장 프로그램 단독 구동·로컬 우선이 확정 사항이다.** 사용자 자료의 업로드 서버·DB 서버·계정은 사용하지 않는다. ONLYOFFICE Docs는 참고·평가 대상으로만 보고 런타임 의존성으로 사용하지 않는다. 웹 발표는 원래 서비스 접속에만 인터넷을 사용한다.

### 0.3 범위 용어

- **현재 발표 자료:** 청중용 출력 화면에 현재 표시되는 단일 자료. 기본 종료의 대상이다.
- **발표 세션:** 동시에 등록된 여러 자료와 해당 진행 상태, 수정 레이어, 수업 도구 설정의 묶음이다.
- **발표 창(Player):** 청중 화면에 실제로 나타나는 슬라이드 및 영상·음원 출력 창이다.
- **실행 메뉴(Launcher):** 웨일 툴바 아이콘 클릭 시 표시되는 짧은 시작 메뉴이다.
- **독립 리모컨(Remote):** 별도의 작은 브라우저 창으로, 다른 앱을 클릭해도 일반 액션 팝업처럼 자동 닫히지 않는다.
- **미리보기·편집창(Editor):** 현재 발표와 무관하게 파일 및 슬라이드를 선택하여 추가 레이어·노트·수업 설정을 관리하는 작업공간이다.
- **빠른 수정 레이어:** 원본의 글자/객체를 직접 제거하지 않고 위에 새로운 단색 글상자 등을 겹쳐 표시하는 레이어이다.
- **자료별 복사본:** 현재 자료에서 발생한 변경 사항이 반영된 새 PDF/PPTX 또는 지원되는 결과물이다.
- **수업 편집정보 파일:** 원본 파일 참조, 진행 상태, 글상자/판서/노트/자동재생 설정 등을 재편집하기 위해 로컬 PC에 저장하는 전용 데이터이다. 브라우저의 임시 작업본과 구분한다.

## 1. 해결할 문제와 성공 기준

### 1.1 실제 문제

- 교사가 발표를 띄운 후 다른 프로그램을 클릭하면 기존 발표 방식에 따라 영상·음원·자동 넘김·효과의 진행이 중단될 수 있다.
- PDF, PPTX, 한쇼, 온라인 슬라이드를 번갈아 사용할 때 프로그램과 창을 반복해서 바꿔야 하고, 이전에 보고 있던 페이지를 다시 찾아야 한다.
- PPTX·PDF의 글자를 한두 줄 수정하려고 정식 편집기를 열거나 발표를 종료하는 과정이 번거롭다. 읽기 전용 자료는 더욱 그렇다.
- 학생에게 보이는 화면을 바꾸지 않고, 교사만 다음 슬라이드에 메모·글상자를 미리 넣기 어렵다.
- 판서·타이머·가리개·화이트보드·발표자 메모를 여러 프로그램으로 분산해 사용한다.
- 원본 파일을 덮어쓸 위험과 수업 중 변경 사항을 잃을 위험이 있다.

### 1.2 경험 목표

- 툴바 확장 아이콘에서 즉시 기존 수업 세트를 불러온다.
- 자료 A의 5페이지 → 자료 B의 2페이지 → 자료 A의 5페이지처럼 즉시 교차한다.
- 발표하는 동안 교사는 다른 앱을 자유롭게 조작할 수 있고, 발표 창의 미디어는 해당 자료에 설정한 정책에 따라 정상 진행한다.
- 발표 화면에 바로 우클릭하거나 비공개 미리보기에서 다른 슬라이드에 글상자를 추가한다.
- 자료별로 개별 종료하거나 한 번에 전체 종료하며, 변경된 자료의 복사본을 선택하여 저장한다.

### 1.3 성공 조건

- **빠른 접근:** 실행 아이콘 → 최근 수업 이어하기 → 발표 및 리모컨 복원까지 최소 단계로 완료한다(시간 목표는 실측 후 설정).
- **진행 상태:** 파일 간 왕복 전환 시 문서별 페이지가 일치하고 편집 레이어가 보존된다.
- **재생 독립성:** 발표 창이 표시된 채 다른 프로그램을 5분 이상 조작해도 지원되는 미디어 및 자동 넘김이 의도치 않게 멈추지 않는다.
- **비공개 편집:** 교사가 다른 페이지를 수정하는 동안 청중용 발표 화면이 바뀌지 않는다.
- **안전한 종료:** 취소·저장 실패·브라우저 중단 상황에서도 원본 손상 없이 데이터 복구가 가능하다.

## 2. 지원 형식과 실제 실행 방식

| 콘텐츠 | 확장 프로그램을 통한 시작 | 권장 재생 구조 | 1차 주요 기능 | 핵심 제약 |
|---|---|---|---|---|
| PDF | 로컬 파일 선택 | PDF.js 기반 자체 플레이어 | 페이지 이동, 자동 넘김, 판서, 글상자, 메모, PDF 복사본 | 일부 대화형 폼·3D·특수 기능 차이 가능 |
| PPTX | 로컬 파일 선택 | 전용 PPTX 파서/렌더러 및 미디어 해석기 | 슬라이드 이동, 레이어 수정, 노트, 지원 범위 내 오디오·영상 | 도형, 테마, 애니메이션, 전환·폰트 호환성 |
| 구형 `.ppt` | 파일 선택 | 변환 기술 또는 별도 파서 | 변환 후 발표·레이어 | 직접 파싱 난도 높음. 초기 완전 지원 보장 금지 |
| 한쇼 `.show` | 파일 선택 | 허용된 렌더링/변환 기술 검증 | 변환 성공 자료의 발표·레이어 | 전용 형식 분석·재생 엔진 미확정 |
| 캔바 발표 링크 | URL 등록 | 캔바 원본 브라우저 페이지의 관리형 실행 | 창/링크 관리, 세션 등록, 분리 노트 | 페이지 인식·자동 전환·오버레이·전체화면 제어 검증 필요 |
| 미리캔버스 발표 링크 | URL 등록 | 미리캔버스 원본 브라우저 페이지의 관리형 실행 | 창/링크 관리, 세션 등록, 분리 노트 | 동일. 사이트 UI 변경·로그인·공유 권한에 영향 |

**핵심 원칙:** 모든 자료는 확장 프로그램을 **거쳐 실행**하되, 렌더링까지 모두 우리 코드가 수행해야 하는 것은 아니다. 온라인 링크는 원본 서비스를 존중하는 별도 어댑터를 둔다.

### 2.1 온라인 링크 연동 수준

- **W0 — 링크·창 관리:** URL 등록, 권한/로그인 안내, 새 탭/창 실행, 최근 전환, 세션 노트 보관. 기본 제공 목표.
- **W1 — 표시 보조:** 사이트와 브라우저 보안 설정에서 가능한 경우 판서·가리개·타이머·빠른 수정 오버레이를 제공한다. 사이트별 실험 필요.
- **W2 — 실제 슬라이드 상태 연동:** 현재 페이지 표시, 원격 페이지 이동, 자동 넘김, 마지막 위치 정확 복원. 공식 연동 수단 또는 검증된 안전한 어댑터가 확인될 경우 제공.
- **W3 — 미리보기 비공개 편집:** 온라인 발표의 특정 슬라이드에 대한 비공개 미리보기 및 우리 오버레이 편집. 자체 API·사이트 구조·보안 제약 충족 시에만 지원한다.

**지원 불가 시 처리:** 불가능한 버튼을 표시만 해 두지 않는다. '이 사이트에서는 해당 기능 미지원'을 알리고 원본 서비스의 발표 기능으로 돌아가는 경로를 제공한다. iframe 내장, DOM 접근, 키보드 이벤트 모방, 페이지 캡처, 전체 화면 위 오버레이는 모두 별개의 검증 항목이다.

## 3. 창 구성 및 모니터 운영

### 3.1 네 가지 UI

1. **Launcher:** 확장 아이콘 → `최근 수업 이어하기`, `새 수업`, `파일 추가`, `발표 링크 추가`, `리모컨 다시 열기`, `설정`.
2. **Player:** 슬라이드 출력, 미디어 재생, 자동 진행, 판서·글상자 렌더링, 청중용 화면 최소 UI.
3. **Remote:** 자료 선택, 마지막 페이지 표시, 이전/다음, 재생·정지, 자동 넘김, 노트, 타이머, 편집창 열기, 현재 자료 종료, 일괄 종료.
4. **Editor:** 파일 목록, 슬라이드 썸네일, 비공개 미리보기, 글상자 생성·이동·조절, 폰트 및 글씨 크기, 노트·수업 도구 설정.

### 3.2 두 모니터 기본값

```text
[모니터 1 — 교사용]                       [모니터 2 — 청중용]
┌──────────────────────────────┐      ┌──────────────────────────────┐
│ 웹/업무/교사용 프로그램       │      │                              │
│ ┌──── 독립 리모컨 ────────┐ │      │     실제 발표 슬라이드       │
│ │ [PDF1 5쪽][PPT2 2쪽]   │ │      │   + 판서·글상자·가리개       │
│ │ ▶/Ⅱ · 자동넘김 · 노트   │ │      │   + 영상/음원/효과           │
│ │ 현재 종료 | 일괄 종료   │ │      │                              │
│ └─────────────────────────┘ │      └──────────────────────────────┘
│ ┌── 비공개 미리보기 편집창 ─┐ │
│ │ PPT2 8번 슬라이드 편집   │ │
│ │ (청중 화면 변경 없음)    │ │
│ └─────────────────────────┘ │
└──────────────────────────────┘
```

- 연결된 TV·전자칠판·프로젝터는 **화면 출력 장치일 뿐 제품의 필수 조건이 아니다.** 확장/복제 모드의 차이는 중요하다.
- 기본은 **확장 디스플레이**로 모니터를 분리해 활용한다. 복제 모드에서는 교사용 창이 청중에게 노출될 수 있음을 알린다.
- 사용자가 발표 모니터를 지정할 수 있고 최근 설정을 복원한다. 연결 해제 또는 해상도 변경 시 창을 안전한 화면으로 이동한다.
- 리모컨은 독립 팝업형 브라우저 창으로 구현한다. 웨일 확장 아이콘에 달린 일반 액션 팝업과 혼동하지 않는다.
- 단일 모니터에서는 발표 창을 전면에 두고 리모컨을 필요시 열거나 다른 탭에서 관리한다. 교사용 노트의 청중 노출을 경고한다.
- **리모컨 클릭으로 청중 화면의 영상이 멈춰서는 안 된다.** 그러나 운영체제의 마우스·키보드 포커스 자체를 완전히 격리하는 기능은 이 프로젝트의 범위 밖이다.

### 3.3 비공개 미리보기의 필수 조건

- `presentedDocumentId/presentedSlideId`와 `editorDocumentId/editorSlideId`를 서로 다른 값으로 유지한다.
- Editor에서 파일이나 슬라이드를 클릭하는 것만으로 Player가 전환되지 않는다.
- 다른 슬라이드를 수정하면 편집 레이어를 즉시 임시 저장하되, 청중 화면은 그대로 유지한다.
- 현재 발표 중인 슬라이드를 편집할 경우, 기본은 **편집 확정 후 발표 화면 반영**으로 하고 설정에서 `수정 즉시 반영`을 선택할 수 있게 한다.
- Editor의 영상 미리보기는 기본적으로 정지된 포스터/첫 프레임이다. 편집창에서 영상을 재생해도 발표 창 미디어 상태를 임의로 건드리지 않는다.
- Editor에서 지정한 글상자 좌표는 화면 픽셀 기준이 아니라 **원본 슬라이드의 논리 좌표/정규화 좌표**로 저장한다.

## 4. 멀티 프레젠테이션 및 문서별 진행 상태

### 4.1 기본 작동

- 세션에 여러 로컬 파일과 온라인 링크를 함께 등록한다.
- 자료 A의 5쪽 → 자료 B의 2쪽 → 자료 A로 돌아오면 A의 **5쪽**을 출력한다.
- '이전 자료로 돌아가기'와 즐겨찾는 자료/슬라이드 바로 가기를 별도로 지원한다.
- **자료 전환**과 **같은 자료 안에서 페이지 넘김**은 다른 명령으로 구현한다.
- 파일 목록 순서를 변경해도 자료의 고유 ID와 내부 슬라이드 ID가 유지되어야 한다.

### 4.2 자료별 저장 상태

| 범주 | 상태 |
|---|---|
| 진행 | 문서 ID, 현재 슬라이드 ID, 페이지 번호, 확대율·이동 좌표 |
| 콘텐츠 수정 | 추가 글상자 목록, 색·폰트·정렬·좌표·크기·z-index, 실행 취소 이력 |
| 판서·수업 도구 | 판서 획, 가리개 상태, 슬라이드별 오버레이, 타이머 범위 |
| 재생 | 음원·영상 타임코드, 재생/일시정지, 자동 넘김 모드와 시간 |
| 메모 | 원본 PPTX 발표자 노트(가져오기 가능 범위), 우리 노트, 수업 진행 기록 |
| 저장 | 변경 상태(dirty), 마지막 복구 시각, 복사본 내보내기 이력 |

### 4.3 자료 전환 정책

1. 기존 활성 자료의 페이지·편집 상태를 확정하고 복구 저장한다.
2. **다른 발표 자료로 넘어가는 경우** 기존 자료의 영상·음원·자동 넘김은 기본적으로 일시정지한다.
3. 이동할 자료의 마지막 페이지와 오버레이를 복구한다.
4. 복귀 시 미디어는 **기본 '일시정지한 위치에서 대기 → 사용자가 재개'**로 한다. 자동 재개·처음부터 재생은 자료별 선택 설정으로 지원한다.
5. 수업 전체 타이머는 자료 간 이동과 독립적으로 유지할 수 있다.
6. 온라인 발표는 서비스가 지원하는 범위만 정확히 복원한다. 페이지 복원이 불가능하면 링크를 유지하되 '마지막 슬라이드 자동 복원 미지원'을 표시한다.

## 5. 포커스 독립 재생: 반드시 구현할 최상위 요구사항

### 5.1 목표

**Player가 청중 화면에 표시되어 있는 동안, 사용자가 리모컨·편집창·다른 웨일 탭·문서 프로그램을 클릭하더라도 현재 활성 발표의 재생이 중단되지 않아야 한다.**

적용 대상:
- HTML5 동영상, 음원 등 플레이어가 직접 관리하는 미디어
- 구현/검증된 PPTX 애니메이션·전환 효과
- PDF/PPTX 슬라이드 자동 넘김
- 경과 시간 기반 타이머·초시계
- 지원 가능한 PDF/PPTX 페이지별 재생 시나리오

### 5.2 설계 원칙

- 재생 시간의 유일한 기준은 **발표 플레이어의 재생 상태와 경과 시간**이다. 리모컨 창의 열린 상태나 키보드 포커스에 의존하지 않는다.
- 시간 제어는 실제 시간 기반 타임라인과 미디어 이벤트(`ended`, `timeupdate` 등)를 이용한다. 단순한 `setInterval` 호출 횟수를 진실의 원천으로 삼지 않는다.
- 초기 소리 재생은 브라우저 자동재생 정책에 맞춰 사용자의 `발표 시작` 제스처로 시작한다. 이후 미디어별 자동 시작은 허용 조건·코덱·재생 실패를 검사한다.
- 미디어와 자동 넘김은 **현재 활성 자료에서만** 진행한다. 리모컨 닫기/편집창 열기는 중단 사유가 아니다.
- 애니메이션은 '지원 가능', '정적 대체', '원본과 차이'를 판별할 수 있어야 한다. 미지원 효과를 무조건 동작한다고 광고하지 않는다.
- **표시 중인 전용 발표 창**과 **실제로 최소화·숨김 처리된 창**은 구분한다. 화면이 숨겨진 환경의 시각 효과는 브라우저 최적화 정책에 영향을 받을 수 있으므로 별도 실험 대상이다.
- 캔바·미리캔버스의 내부 자동재생을 강제로 지속시키는 기능은 보장하지 않는다. 서비스 별 재생 중단 시 대체 방식이나 안내를 제공한다.

### 5.3 자동 넘김 설정

- 전체 기본값 / 자료별 / 슬라이드별 값을 제공하고 우선순위는 **슬라이드 > 자료 > 세션 기본값**이다.
- `N초 후 다음`, `영상·음원 종료 후 다음`, `둘 중 늦은 시점`, `수동 전용`을 제공한다.
- 슬라이드 반복, 범위 반복, 전체 반복, 시작 시 자동 넘김을 설정할 수 있다.
- 타이머·판서·화이트보드 사용 중에는 자동 넘김을 일시정지할 수 있다(사용자 설정).
- 다른 발표 자료로 전환하면 기존 자료의 자동 넘김은 멈추고 그 타이밍 상태를 보관한다.
- 자동 넘김 예약이 실행 실패한 경우 오류를 기록하고 리모컨에서 상태를 확인할 수 있어야 한다.

## 6. 빠른 수정: 단색 배경 맞춤 글상자

### 6.1 적용 영역과 목적

- 현재 발표 중인 **Player 화면**과 비공개 **Editor 미리보기 화면** 모두에서 동일하게 사용한다.
- 읽기 전용 PPTX, 이미지화된 슬라이드, PDF에도 동일한 추가 레이어 방식으로 작동한다.
- 원본의 기존 텍스트를 실제로 지우는 것이 아니라 배경색과 같은 단색 상자로 가리고 새 텍스트를 표시한다.
- **단색 배경만 보장한다.** 복잡한 사진/그라데이션/무늬 위의 자연스러운 복원은 이번 핵심 개발 범위에서 제외한다.

### 6.2 사용자 동작

1. 사용자가 발표 화면 또는 미리보기 화면을 **우클릭**한다. 터치는 **길게 누르기** 또는 화면 내 `빠른 수정` 도구 선택으로 대체한다.
2. 컨텍스트 메뉴에서 `이 위치에 글상자 추가`를 선택한다.
3. **클릭 지점의 실제 색상**과 **주변의 대표 단색 배경** 두 후보를 보여준다. 두 색이 거의 같으면 한 개로 표시한다.
4. 사용자가 배경색을 선택한다. **검정 픽셀을 클릭한 경우 주변색을 강제로 선택하지 않는다.** 검정 배경이 의도된 것일 수 있기 때문이다.
5. 커서를 드래그해 글상자의 **가로·세로 크기를 먼저 확정**한다. 드래그가 끝나면 즉시 글자 입력에 들어간다.
6. 입력된 내용은 글상자 크기 안에 가능한 **가장 큰 글자 크기**로 자동 맞춰진다. 입력 때문에 상자 크기가 변하지 않는다.
7. 모서리 대각선 핸들을 드래그하면 상자의 너비와 높이를 재조정하고, 글씨 크기를 다시 계산한다.
8. `−`/`+`로 글자 크기를 수동 조절하고 `자동`으로 최적화에 복귀한다. 텍스트·배경·폰트·정렬을 언제든 바꿀 수 있다.
9. 현재 발표 화면의 변경은 확정 후 즉시 반영하거나, 설정에 따라 입력 중 실시간 반영한다. 다른 슬라이드 편집은 해당 슬라이드가 실제로 발표될 때 보인다.

### 6.3 색상 규칙

| 조건 | 글상자 배경색 | 기본 글자색 | 참고 |
|---|---|---|---|
| 클릭 지점과 주변이 같은 단색 | 자동 단일 선택 | 검정색(일반 배경) | 선택 단계 생략 가능 |
| 클릭 지점이 검정이고 주변이 다른 색 | **검정 / 주변색**을 사용자 선택 | 검정 선택 시 **흰색** | 검정을 오인으로 치부하지 않음 |
| 클릭 지점이 다른 유색 | 클릭색 / 주변 대표색 선택 | 기본 검정 | 사용자가 변경 가능 |
| 사진·그라데이션 | 단색 후보만 제공 | 사용자 조절 | 완전한 가림 품질 보장하지 않음 |

- 색상 후보는 실제 슬라이드 렌더링의 픽셀 샘플을 사용한다. 주변 대표색은 가장자리/주변 패치의 최빈 색·유사색 군집 등으로 추정한다.
- 원본 슬라이드와 그 위에 이미 추가된 오버레이를 분리하여 샘플링할 수 있게 한다. 원본색 추출과 화면 전체 색 추출 중 어떤 결과인지 UI에 설명한다.
- 명도 대비가 부족하면 보조 경고를 표시한다. 색상 자체를 사용자의 선택 없이 바꾸지 않는다.

### 6.4 글상자 크기와 글씨 자동 맞춤

- **사용자가 지정한 글상자 영역은 고정**한다(자동 확대 금지).
- 가로·세로 중 **더 엄격한 배치 제약**을 만족하는 가장 큰 글씨 크기를 선택한다.
- 실제 선택 폰트의 가로폭, 줄바꿈, 행 높이, 내부 여백, 줄 간격을 사용해 후보 크기를 측정한다.
- 줄을 무조건 하나로 유지하지 않는다. 두 줄·세 줄이 더 큰 글씨를 허용하면 자동 줄바꿈을 고려한다.
- 사전 설정에 `최소 글씨 크기`, `최대 글씨 크기`, `기본 폰트`, `내부 여백`, `가로·세로 정렬`, `줄 간격`을 제공한다.
- **최소 크기보다 작아야만 들어갈 경우** 텍스트를 임의로 숨기거나 계속 축소하지 않고 '상자를 늘리거나 내용을 줄이기' 경고를 표시한다.
- 수동 `+`로 상자 밖으로 넘치면 초과 경고를 표시하고 `자동` 복귀를 제공한다.
- 한글 IME 조합 중에는 크기 변화가 과하게 출렁이지 않도록 조합 완료 후 확정 계산하거나 부드럽게 갱신한다.

### 6.5 편집 레이어의 객체 조작

- 텍스트 입력, 재편집, 선택, 이동, 복제, 삭제, 되돌리기/다시 실행을 제공한다.
- 글상자 **내부 텍스트 클릭 → 편집**, 글상자 **테두리 드래그 → 위치 이동**, **모서리 핸들 드래그 → 크기 조절**로 역할을 구분한다.
- 글상자 `z-index`와 슬라이드별 편집 레이어의 순서를 저장한다.
- 기존 PPTX 원본 텍스트는 글상자를 삭제하면 다시 보일 수 있음을 내보내기 시 명시한다.
- 단색 글상자 생성과 판서 기능은 각각 독립된 레이어로 저장해 필요에 따라 표시·숨김 처리할 수 있게 한다.

## 7. 폰트 지원 정책

- 기본 라이선스 검토 완료한 한글 웹폰트를 확장 프로그램에 **포함**할 수 있다(예: 사용 허가 조건을 확인한 오픈 라이선스 폰트).
- 사용자의 PC에 설치된 글꼴을 이용하는 경로는 브라우저의 허용 API와 사용 권한을 검토한다.
- 사용자가 로컬 TTF/OTF/WOFF2 파일을 선택하여 **프로그램 내에서만 추가 사용**하는 경로를 제공한다.
- 온라인 웹폰트는 네트워크와 이용 조건에 의존하므로, 오프라인 수업을 위해 기본 폰트를 함께 준비한다.
- 빠른 글상자에는 다양한 폰트를 적용할 수 있으나 **기존 PPTX에 사용된 누락 폰트가 자동 완벽 복구되는 것은 아니다.** 대체 폰트 제안과 표시 차이 안내가 필요하다.
- PDF/PPTX 복사본 내보내기에서는 라이선스에 따른 폰트 포함 허용, 대체 폰트, 글자 깨짐, 슬라이드 크기 재측정을 검사한다.
- 발표 미리보기와 실제 출력 창에서 동일한 폰트 파일·로드 완료 상태를 공유하여 줄바꿈 불일치가 없도록 한다.

### 8.2 발표자 노트

- 노트는 **청중용 Player에 표시하지 않는다.** 리모컨과 Editor에만 표시한다.
- PPTX 원본의 Notes Slide를 해석할 수 있으면 초기 값으로 읽어온다. 우리 프로그램에서 쓴 메모와 수업 진행 기록은 별도로 유지한다.
- PDF와 한쇼의 원본 노트 추출이 어려워도 확장 프로그램 전용 노트를 생성한다.
- 파일을 교차해도 해당 슬라이드의 노트가 자동으로 전환된다.
- 리모컨에서 글씨 크기, 현재/다음 슬라이드 썸네일, 개인 메모 검색을 지원한다.
- 화면 복제 시 노트가 노출될 수 있음을 경고한다.

### 8.3 타이머와 자동 넘김의 관계

- 발표 자료가 바뀌어도 **세션 전체 타이머**는 설정에 따라 계속 진행한다.
- **자료별 슬라이드 자동 넘김**은 비활성 자료로 바뀌는 즉시 정지한다.
- 글상자 편집 중 또는 판서 중 자동 넘김을 일시정지하도록 옵션을 제공한다.
- 모든 도구를 원본과 분리해 관리하여 저장 시 선택적으로 포함한다.

## 9. 현재 자료 종료·일괄 종료 및 안전한 복사본 저장

### 9.1 종료 명령

| 명령 | 기본 대상 | 나머지 자료 | 완료 후 청중 화면 |
|---|---|---|---|
| **현재 자료 종료** | 현재 발표 중인 자료 1개 | 실행 상태·진행 위치·편집 레이어 유지 | 기본은 **검정 대기 화면**, 교사가 다음 자료 선택 |
| **모든 자료 일괄 종료** | 세션에 등록된 자료 전체 | 해당 없음 | 세션 종료·발표 창 닫기 또는 종료 화면 |

- 리모컨의 기본 종료 버튼은 항상 **현재 자료 종료**에 연결한다.
- `모두 종료`는 별도 버튼 및 확인 과정을 거친다.
- Editor에서 현재 발표 자료 외의 파일만 닫는 동작을 지원하되, '현재 자료 종료'와 명칭을 혼동하지 않는다.
- 일부 자료만 종료해도 나머지 자료의 마지막 슬라이드와 교사용 메모를 유지한다.
- 현재 자료가 종료되면 **다른 파일을 임의로 청중 화면에 자동 노출하지 않는다.** 검정 대기 화면을 기본값으로 한다.
- 웹 발표 탭/창을 닫을 때는 교사가 해당 사이트에서 저장되지 않은 **사이트 자체 편집 상태**가 있는지 확장 프로그램이 알 수 없으므로 주의 문구를 표시한다.

### 9.2 저장 원칙

1. **원본 파일을 기본적으로 절대 덮어쓰지 않는다.** 자료별 결과는 새 복사본으로 저장한다.
2. **변경 사항이 없는 자료는 복사본 생성 대상에서 제외**한다(사용자가 '복사본으로 내보내기'를 별도로 요청한 경우는 예외).
3. 개별 종료의 저장 선택은 **해당 자료의 변경 내용**에만 적용한다. 일괄 종료는 모든 자료의 변경 여부를 요약하고 **자료별로 체크**할 수 있게 한다.
4. **수업 편집 데이터 파일 로컬 저장과 자료별 결과물 복사본 저장을 별도 선택**으로 제공한다. 편집 데이터는 노트·진행 상태·자동재생 설정을 가장 완전하게 유지하며, 브라우저 IndexedDB는 임시 작업본일 뿐 정식 다운로드를 대체하지 않는다.
5. 저장 실패 시 해당 자료와 변경 내용을 삭제하지 않는다. 다시 시도하거나 로컬 임시 저장을 이어갈 수 있어야 한다.
6. 원본을 열 수 없거나 온라인 발표 링크인 경우에도 **전용 세션 데이터**는 보존할 수 있어야 한다.
7. `저장하지 않고 종료` 시에도 임시 복구 기록의 정리 정책을 명시한다. 사용자가 '저장 안 함'을 선택하면 최종 저장이 생성되었다고 표시하지 않는다.

### 9.3 복사본 저장 옵션

| 저장 형태 | 저장 내용 | 특성 |
|---|---|---|
| **수업 편집 데이터 로컬 파일로 저장(필수)** | 자료/링크 목록, 파일 연결 정보, 슬라이드 상태, 글상자·판서, 노트, 타이머, 재생 설정 | 사용자 PC에 저장되는 정식 백업. 확장 재실행·재편집에 적합 |
| **PDF 복사본(필수 우선)** | 각 페이지에 표시된 수정 레이어를 합성한 PDF | 화면 보존에 유리. 자동재생·미디어 등은 별도 세션에 남김 |
| **PPTX 복사본(후속)** | 가능한 경우 원본 슬라이드의 기존 구조에 추가 글상자 삽입, 불가하면 이미지 기반 슬라이드 + 추가 객체 | 원본 애니메이션·미디어 일부가 달라질 수 있음 |
| **한쇼/구형 PPT 결과물** | 해당 형식 그대로의 저장 대신 PDF 또는 PPTX 복사본 | `.show`·`.ppt` 원본 완전 호환 저장은 요구하지 않음 |
| **온라인 발표 결과** | 기존 웹 URL + 우리 오버레이·노트·재생 설정을 세션에 저장, 가능한 경우 별도 PDF 등 내보내기 | 캔바/미리캔버스 원본 웹 문서에 자동 반영하지 않음 |

**파일명 규칙 예시:** `사회교과서_수정본.pdf`, `사회교과서_수정본(2).pdf`처럼 기존 이름과 충돌하지 않는 새 이름을 생성한다. 사용자가 다운로드를 실행하면 최종 결과는 반드시 실제 로컬 PC 파일로 기록한다. 기본 Downloads 폴더 또는 `saveAs`로 선택한 위치를 사용하며, 저장 경로 접근 권한을 임의로 가정하지 않는다.

```text
[리모컨: 현재 자료 종료]        [리모컨: 모두 종료]
             │                         │
       현재 자료 변경 감지       열려 있는 자료 목록/변경 감지
             └──────────┬──────────────┘
                        ↓
         [세션 저장 여부] + [자료별 복사본 저장 여부]
                        ↓
         선택된 항목 내보내기/저장 결과 확인
                        ↓
               성공한 자료만 종료 확정
                        ↓
         (현재 종료: 대기 화면) / (일괄: 세션 종료)
```

- 기본적으로 **저장 내역이 없다면 확인 단계를 축약**한다.
- 수정 사항이 있는 자료에 대해 `복사본 저장`, `세션에만 저장`, `저장하지 않기`, `취소`를 명확히 구분한다.
- 종료 직후 세션 자동 복구를 지원할지, 명시적으로 '저장하지 않기'를 선택한 내용의 임시 보존 기간을 어떻게 할지는 개인정보·스토리지 설계와 함께 결정한다.

## 10. 저장 상태·데이터 모델·동기화 설계

### 10.1 논리 상태 모델 예시

```ts
interface ClassSession {
  id: string;
  title: string;
  presentedDocumentId: string | null; // 청중용 Player
  editorSelection: { documentId: string; slideId: string } | null;
  documentOrder: string[];
  documents: Record<string, PresentationDocumentState>;
  history: { documentId: string; slideId: string }[];
  globalTools: { timer?: TimerState; board?: BoardState };
  output: { preferredDisplayId?: string; standbyScreen: 'black' | 'title' };
  updatedAt: number;
}
interface PresentationDocumentState {
  id: string;
  sourceType: 'pdf' | 'pptx' | 'ppt' | 'show' | 'canva' | 'miricanvas';
  sourceRef: { name?: string; url?: string; handleId?: string };
  currentSlideId: string;
  lastSlideNumber: number;
  slides: Record<string, {
    overlays: TextBoxOverlay[];
    drawings: DrawingStroke[];
    masks: MaskOverlay[];
    presenterNote?: string;
    classLog?: string;
    autoplay?: AutoplayRule;
  }>;
  media: { timeSec: number; paused: boolean; replayPolicy: 'ask' | 'resume' | 'restart' };
  dirty: boolean;
  adapterCapabilities: string[];
}
interface TextBoxOverlay {
  id: string;
  x: number; y: number; width: number; height: number; // 원본 기준 정규화 좌표
  backgroundColor: string;
  color: string;
  fontFamily: string;
  minFontPx: number; maxFontPx: number;
  text: string; fitMode: 'auto-max' | 'manual';
  fontPx?: number;
  align: 'left' | 'center' | 'right';
  verticalAlign: 'top' | 'middle' | 'bottom';
  zIndex: number;
}
```

위 타입은 구현 방향을 설명하는 초안이다. 애니메이션 상태, 다중 오디오 트랙, 회전된 슬라이드, 폰트 캐시, 복구 저널 등은 구현 시 추가한다.

### 10.2 모듈과 메시지

```text
Extension Launcher / Background Coordinator
               │
               ▼
        Session State Store ── IndexedDB (수정 레이어·노트·복구 로그)
               │              └─ chrome.storage (설정·창 위치·최근 세트)
     ┌─────────┼──────────┐
     ▼         ▼          ▼
  Player     Remote      Editor
     │         │          │
     ├─ PDF / PPTX Renderer   └─ 비공개 썸네일/편집 레이어
     ├─ Media & Timeline
     ├─ Overlay Composer
     └─ Online Provider Adapter (Canva / Miricanvas; 단계적)
```

- 메시지는 `COMMAND`, `STATE_UPDATE`, `ACK`, `ERROR`, `MEDIA_EVENT`, `SAVE_RESULT` 등으로 유형을 분리한다.
- **Player를 재생 상태의 실행 주체**로 두고 Remote/Editor는 명령 전달과 데이터 편집을 담당한다.
- **백그라운드 서비스 워커 메모리를 영구 저장소로 사용하지 않는다.** MV3 서비스 워커는 유휴 종료될 수 있으므로 상태를 IndexedDB/chrome.storage에 기록한다.
- 모든 수정 명령은 `sessionId`, `documentId`, `slideId`, `revision`을 포함해 다른 자료에 잘못 반영되지 않도록 한다.
- 미리보기용 렌더링은 실제 Player 미디어를 재생시키지 않고 별도 렌더링 컨텍스트에서 수행한다.
- 활성 Player에는 현재 화면 렌더링을 위한 리소스를 우선 배정한다. 비활성 자료는 상태만 유지하고 필요시 렌더링을 재개한다.

### 10.3 파일·수업 세트 보관 정책

- **로컬 우선 확정:** 별도 백엔드·회원가입·클라우드 DB·사용자 파일 업로드를 만들지 않는다. 원본은 PC에 두고, 편집 정보만 IndexedDB에 임시 저장하며, 최종 편집정보 파일과 결과물 복사본은 사용자의 로컬 PC에 다운로드한다.
- 파일 핸들 및 권한 지속성은 브라우저 구현에 따라 다르므로, 다시 열 때 재선택이 필요한 경우 해당 파일만 안내한다.
- **브라우저 저장소는 결과물 보관소가 아니다.** IndexedDB는 편집 델타·일시 복구 및 참조를, OPFS는 필요한 경우에만 크기 제한 캐시를, `chrome.storage.local`은 작은 설정을 보관한다. 대용량 원본·미디어를 자동으로 IndexedDB/OPFS에 통째로 복제하지 않는다.
- 최종 다운로드 파일(PDF/PPTX 복사본, 편집정보 세션 파일, 묶음 ZIP)은 **반드시 사용자의 로컬 PC**에 실재해야 한다. 실제 다운로드 완료를 확인하고, 실패하면 원본과 편집 상태를 유지한다.
- 로컬 편집정보 파일은 원본 파일을 참조하며, 원본이 이동한 경우 재연결 안내를 제공한다. 자체 포함형 ZIP 패키지는 후속 지원으로 분리한다.
- 대용량 미디어를 중복 복제해 무한 저장하지 않고 사용자 원본을 참조하거나 명시적 패키지 내보내기를 제공한다.
- 세션 공유용으로 원본 콘텐츠까지 포함하는 묶음 파일을 만드는 것은 용량·저작권·개인정보를 검토해 후속 개발한다.
- 원본 파일에서 불러온 PPTX 노트에 학생 이름 등 개인정보가 있을 수 있으므로 로컬 처리, 명시적 내보내기, 데이터 삭제 기능을 제공한다.

## 11. 기술 설계의 현실적 제약과 해결 순서

### 11.1 핵심 기술 위험

| 문제 | 영향 | 먼저 확인할 해결 방향 |
|---|---|---|
| PPTX 고충실도 렌더링 | 애니메이션·영상·글꼴 깨짐 | 사용 빈도가 높은 테스트 파일로 렌더러·미디어 해석기 검증 |
| 구형 PPT/한쇼 직접 실행 | 직접 지원 난이도 높음 | 내보내기·허용된 변환·서드파티 연동의 라이선스 조사 |
| 온라인 발표 페이지 보조 | 교차 출처·iframe·사이트 DOM·전체화면 제약 | 원본 창 실행 W0 선행, W1/W2/W3 분리 실험 |
| 미디어 포커스 독립성 | 수업 중 영상·음원 중단 | 보이는 전용 발표 창 + 재생 타임라인 + 실기기 테스트 |
| 웹 자동재생 정책 | 첫 음원 자동 시작 실패 | 사용자 `발표 시작` 버튼, 재생 실패 안내 및 재시도 |
| 큰 PDF/PPTX 동시 등록 | 메모리·프레임 저하 | 지연 렌더링, 썸네일 캐시, 비활성 문서 경량화 |
| 폰트 | 화면과 복사본 불일치 | 내장 폰트·선택적 사용자 폰트·내보내기 라이선스 점검 |
| 원본과 복사본 저장 호환성 | 일부 효과·미디어 손실 | 세션 저장을 주력으로 유지하고 PDF→PPTX 저장은 단계별 |
| 교사용 노트 노출 | 정보 노출·UX 문제 | 출력 모니터·미러링 감지/안내, 리모컨 창 분리 |
| 모니터 분리·재연결 | 창 위치 유실 | 화면 재탐색·창 위치 안전 복원 |

### 11.2 확장 프로그램으로 가능한 것과 아닌 것

- **가능성이 높은 영역:** 툴바 실행, 별도 창·리모컨, 자체 PDF 보기, 파일별 상태, 빠른 수정 레이어, 판서, 노트, 타이머, 세션 저장.
- **검증이 필수인 영역:** PPTX 원본 효과의 고충실도 재현, 파일별 실제 자동재생 조건, 설치 없는 `.ppt`/`.show` 직접 처리, 캔바·미리캔버스 내부 슬라이드 이동 및 비공개 편집.
- **범위 밖인 영역:** OS 수준에서 모니터 2의 터치와 교사 마우스·키보드를 완전히 독립시키는 입력 격리, 모든 사이트의 백그라운드 재생 강제, 기존 Microsoft PowerPoint 프로그램의 편집 엔진을 확장 프로그램 안에 그대로 이식하는 것.

### 11.3 세부 권한·보안

- Manifest V3 및 최소 권한 원칙을 따른다. 온라인 서비스별 사이트 접근 권한은 필요할 때 사용자에게 요청한다.
- 외부 웹사이트 내용 접근·수정 기능은 해당 서비스의 약관 및 브라우저 정책을 따른다.
- 확장 패키지 실행 코드를 원격으로 가져와 평가하는 설계는 Manifest V3 정책과 충돌할 수 있으므로 사용하지 않는다.
- 브라우저 다운로드, File System Access API, IndexedDB 등의 기능은 대상 **웨일 버전과 Windows/macOS 환경에서 실제 작동**하는지 먼저 확인한다.
- 클라우드 연동 없이도 발표 가능한 오프라인 경로를 기본으로 한다(온라인 발표 링크는 제외).

## 13. 단계별 개발 로드맵

### Phase 0. 불확실성 제거용 기술 실험(필수 선행)

- **T-01:** 웨일 MV3에서 Popup 리모컨 + 표시용 Player + 별도 Editor 세 창 열기 및 동기화.
- **T-02:** HDMI 확장 모니터에서 Player만 2번 화면 표시, 교사 앱 포커스 이동 시 미디어/자동넘김 지속.
- **T-03:** PDF.js에서 특정 페이지 썸네일, 원본 좌표 글상자, PDF 다시 열기.
- **T-04:** 실제 교사용 PPTX 10종 이상의 슬라이드·폰트·영상·음원·애니메이션 지원 수준 확인.
- **T-05:** 캔바·미리캔버스의 URL 유형(편집 링크/공유 링크/발표 링크), 로그인, 발표 모드, 우클릭 및 오버레이 허용 범위 실험.
- **T-06:** 선택 파일 복사본 저장과 브라우저 복구, 권한 재요청, 원본 미변경 여부 검사.
- **T-07:** `.ppt`와 `.show`에 대한 실현 가능한 경로·라이선스·외부 프로그램 요구 여부 조사.

**Go/No-Go:** 창 분리·PDF 교차·포커스 독립 재생이 가능해야 핵심 제품 진행. PPTX 엔진과 웹 발표는 기술 결과에 따라 지원 범위를 명시한다.

### Phase 1. 공통 발표 기반(MVP-A)

- 확장 아이콘, 세션 관리자, PDF 플레이어, 리모컨, 두 모니터 선택.
- PDF 여러 개의 교차 전환 및 페이지/상태 기억.
- 기본 자동 넘김과 포커스 독립성 검증.
- 저장·복구 데이터 모델 및 검정 대기 화면.

### Phase 2. 교사용 미리보기·빠른 수정(MVP-B)

- 비공개 Editor, 슬라이드 썸네일, 발표/편집 커서 독립.

## 14. 실제 사용자 시나리오 8종

### S-01. 수업 시작
교사는 웨일 확장 아이콘에서 `5학년 사회` 수업 세트를 연다. PDF와 PPTX, 캔바 링크가 목록에 표시된다. 모니터 2에 발표 화면을 배치하고 모니터 1에 리모컨을 연다.

### S-02. 파일 교차
`교과서.pdf` 5쪽을 설명하다 `문화유산.pptx` 2번 슬라이드를 재생하고 다시 PDF를 선택한다. PDF는 5쪽에서 시작하고 이전 판서도 유지된다.

### S-03. 다른 프로그램 조작
PPTX의 지원되는 영상을 재생한 채 출석 입력 프로그램을 사용한다. Player는 현재 슬라이드와 미디어·자동 진행 상태를 유지한다.

### S-04. 발표 화면 바로 수정
현재 PDF에서 마우스를 우클릭하여 글상자를 추가한다. 클릭한 검정색과 주변 연두색 중 연두색을 선택한다. 사각형을 드래그하고 글자를 입력하면 영역 안에 최대 크기로 표시된다.

### S-05. 비공개 다음 슬라이드 수정
학생에게 PDF 5쪽을 보여 주는 동안 교사는 Editor에서 PPTX 8번 슬라이드에 검정 바탕·흰 글씨의 글상자를 추가한다. PDF 화면은 바뀌지 않는다. 이후 PPTX 8번을 표시하면 글상자가 보인다.

### S-06. 수업 도구와 노트
교사는 발표자 노트에서 발문을 확인하고 5분 타이머를 시작한다. 학생이 발표하는 동안 가리개를 제거하고 판서를 남긴다. 다른 자료로 옮겨도 세션 타이머는 계속 작동한다.

### S-07. 현재 자료만 종료
활성 PPTX를 종료한다. PPTX가 수정되었다면 `세션에만 저장` 또는 `수정본 복사본 저장` 등을 선택한다. 나머지 PDF는 실행 목록에 남고 학생 화면은 검정 대기 화면이 된다.

### S-08. 일괄 종료
수업이 끝나면 `모두 종료`를 누른다. 수정된 PDF·PPTX만 기본 선택되어 있으며 각각 PDF/PPTX 결과물 또는 세션 보관을 선택한다. 완료 후 원본 파일은 모두 변경되지 않았다.

## 16. 공모전 메시지 및 2분 시연 구상

### 16.1 한 줄 설명

> **자료는 여러 개, 발표 화면은 하나. 웨일에서 빠르게 열고, 끊기지 않게 재생하며, 발표 중 바로 수정하는 통합 수업 프레젠테이션 확장 프로그램이다.**

### 16.2 차별점

1. **확장 프로그램 접근성:** 브라우저의 작은 실행 버튼으로 수업 세트를 즉시 연다.
2. **자료 교차 전환:** PDF·PPTX 등 여러 발표의 마지막 위치와 수정 내역을 기억한다.
3. **포커스 독립 재생:** 교사가 다른 프로그램을 조작해도 발표 재생은 계속하도록 설계한다.
4. **교사용 비공개 제어:** 모니터 1에서 다음 슬라이드를 미리 편집해도 청중 화면은 유지한다.
5. **간편한 우클릭 수정:** 기존 편집기 없이 단색 글상자로 빠른 문구 수정.
6. **안전한 종료·저장:** 자료별 개별 종료와 전체 종료, 원본 보존형 복사본 저장.

### 16.3 시연 진행

- 0:00~0:20: 웨일 확장 아이콘에서 수업 세트 열기 및 리모컨 표시.
- 0:20~0:40: PDF 5쪽→PPTX 2쪽→PDF 5쪽 교차 복원.
- 0:40~1:00: PPTX 영상 재생 중 다른 프로그램 사용해도 재생 유지.
- 1:00~1:20: 발표 화면 우클릭→색상 선택→드래그→문구 수정.
- 1:20~1:40: 교사 Editor에서 다른 슬라이드 비공개 편집·메모.
- 1:40~2:00: 현재 자료 종료와 일괄 종료를 보여주고 수정본 복사본 저장 시연.

**주의:** 온라인 링크·한쇼·구형 PPT는 검증 수준에 따라 데모에서 명시적으로 '지원', '시험', '준비 중'을 구분한다.

## 19. AI 개발 에이전트 실행 명세 — **구현 지시의 기준**

이 장은 PRD에 명시된 범위를 실제 코드 작업으로 전환하는 데 사용할 수 있는 실행 명세다. 기술 실험의 결론이 나오기 전에는 임의의 완성도를 주장하지 않는다.

### 19.1 최우선 사용 시나리오(단일 수직 기능)

```text
[웨일 툴바 아이콘 클릭]
    ↓
[파일 2개 이상 등록: A.pdf, B.pdf]  (이후 PPTX 추가)
    ↓
[Player(청중) + Remote(교사) 창 생성]
    ↓
[A.pdf 5페이지] → [B.pdf 2페이지] → [A.pdf 5페이지 정확히 복원]
    ↓
[Editor에서 B.pdf 8페이지를 학생에게 보이지 않게 편집]
    ↓
[우클릭 → 배경색 후보 선택 → 드래그로 고정 글상자 생성]
    ↓
[글상자 내부에서 실제 글꼴 렌더링 측정 → 최대 글자 크기로 자동 맞춤]
    ↓
[교사가 메신저/웹/문서 프로그램 클릭 → Player 발표 지속]
    ↓
[현재 자료 종료 → 브라우저 임시 변경 데이터 정리 전에 로컬 PC로 편집정보 저장/수정본 다운로드 선택]
    ↓
[다른 자료는 열린 상태·마지막 페이지 유지; 전체 종료는 별도 선택]
```

### 19.2 구현 아키텍처(필수 경계)

```text
Manifest V3 extension
├─ service-worker           : 설치/런처/창 관리/메시지 라우팅. 영구 상태를 메모리에 독점 저장 금지
├─ launcher popup           : 실행/최근 세트/파일·링크 추가
├─ player (extension page)  : 선택 문서 렌더링 + media + auto-advance + output overlay
├─ remote (popup window)   : 파일 전환·슬라이드 이동·재생·노트·도구·종료
├─ editor (window/tab)     : 발표와 독립된 비공개 썸네일·편집 레이어·미리보기
├─ session-core            : session/doc/slide 상태, 명령, 리비전, 진행·종료 정책
├─ renderer-adapters       : PDF / PPTX / legacy PPT / HShow / Canva / Miricanvas
├─ overlay-engine          : quick textbox, drawing, mask, coordinate conversion, undo/redo
├─ media-controller        : audio/video timeline, autoplay, visibility/focus handling
├─ persistence             : IndexedDB delta, OPFS bounded cache, file refs, chrome.storage settings
├─ export                  : browser save file + PDF clone + PPTX fallback + session bundle
└─ permissions/security    : selective grants, link validation, sandboxing of untrusted file content
```

- `session-core`는 UI 프레임워크에 종속되지 않는 순수 함수 중심으로 구현한다. Player, Remote, Editor는 같은 명령 인터페이스를 쓰고, 독립적인 리비전 관리와 스냅샷 읽기를 수행한다.
- `Player`는 **현재 발표 콘텐츠를 재생하는 소유자**이다. Remote가 닫혀도 계속 재생해야 한다. Editor의 미리보기는 별도 렌더러/메모리에서 실행하며 재생 주체를 빼앗지 않는다.
- `service-worker`는 명령을 전달하지만 영상 플레이어·자동 넘김 타이머·글꼴 계산을 담당하는 장기 프로세스로 설계하지 않는다.
- 임시 콘텐츠의 저장/복원도 임의의 웹사이트 `localStorage`가 아니라 **확장 프로그램 오리진**의 IndexedDB를 사용한다. Content script 안의 web storage는 **호스트 사이트 저장소가 될 수 있으므로** 이를 혼동하지 않는다.

### 19.3 초기 프로젝트 레이아웃(권장)

```text
whale-class-presenter/
├─ README.md
├─ package.json
├─ tsconfig.json
├─ vite.config.ts
├─ manifest.config.ts             # 배포 시 manifest.json 생성
├─ public/icons/
├─ src/
│  ├─ background/index.ts
│  ├─ launcher/{index.html,main.tsx,Launcher.tsx}
│  ├─ player/{index.html,main.tsx,Player.tsx}
│  ├─ remote/{index.html,main.tsx,Remote.tsx}
│  ├─ editor/{index.html,main.tsx,Editor.tsx}
│  ├─ core/{types.ts,commands.ts,reducer.ts,events.ts,capabilities.ts}
│  ├─ adapters/{types.ts,pdf.ts,pptx.ts,ppt.ts,show.ts,canva.ts,miricanvas.ts}
│  ├─ overlays/{textbox.ts,textFit.ts,colorSampling.ts,canvasOverlay.ts,geometry.ts}
│  ├─ media/{timeline.ts,autoplay.ts,mediaState.ts}
│  ├─ storage/{settings.ts,db.ts,fileHandles.ts,cache.ts,sessionBundle.ts}
│  ├─ export/{download.ts,pdfExport.ts,pptxExport.ts,sessionExport.ts}
│  ├─ shared/{messageBus.ts,guards.ts,errors.ts}
│  └─ styles/
├─ tests/{unit,integration,fixtures,e2e}/
├─ docs/{TECH_SPIKES.md,COMPATIBILITY_MATRIX.md,TEST_RESULTS.md,LICENSES.md}
└─ dist/                          # 웨일 확장 프로그램 개발자 모드에서 로드할 산출물
```

- 위 구조는 **권장 시작점**이다. 개발 환경에 맞게 다듬을 수 있으나 Player/Remote/Editor/Session/Adapters/Overlays/Storage/Export의 책임 분리는 유지한다.
- 런타임에서 원격 서버 코드를 불러오지 않는다. 확장 프로그램에서 실행되는 JavaScript 및 필요한 WASM과 기본 폰트는 배포 패키지에 포함한다. CDN 스크립트, `eval` 기반 로더는 사용하지 않는다.
- 크기와 라이선스를 확인하면서 우선 PDF.js(`pdfjs-dist`)를 쓰고, IndexedDB/OPFS는 불필요한 추상화를 피한 작은 저장 계층으로 작성한다. PPTX 렌더러는 **2종 이상 실험 후** 호환성·라이선스·서버 유무로 고른다.

### 19.4 구현 P0 실험 결과물 (`docs/TECH_SPIKES.md`)

첫 단계에서 코드만 작성하는 것이 아니라 다음 표를 실제 테스트 결과로 채운다.

| 실험 | 반드시 시험할 내용 | 성공 판정 | 실패 시 대안 |
|---|---|---|---|
| X-01 | 네이버 웨일에서 MV3 확장 빌드 로드 및 멀티 창 생성 | Launcher/Player/Remote/Editor 각각 열림 | 브라우저 버전·API 차이를 기록하고 기본 창 열기 |
| X-02 | 듀얼 모니터의 별도 창 위치 제어 | Player를 표시 화면에 배치, Remote 교사용 화면에 배치 | 수동 드래그·모니터 선택 UI |
| X-03 | PDF.js에서 PDF 렌더링·여러 문서 전환 | A 5→B 2→A 5 및 오버레이 상태 유지 | 디코더 또는 렌더링 캐시 조정 |
| X-04 | PPTX 렌더러 후보 비교 | 텍스트·사진·표·미디어 샘플별 차이 기록 | 제한 지원 및 PDF로 변환하기 안내 |
| X-05 | 포커스 이동 중 자동 넘김·음원·영상 | 다른 앱을 클릭해도 발표 중인 지원 콘텐츠 정상 진행 | Player 전용 창·절대시각 타임라인 수정 |
| X-06 | 배경색 후보 추출과 글상자 배치 | 단색 배경/검정 글씨의 두 후보 선택이 정상 | 주변 영역 샘플링 로직 조정 |
| X-07 | File System Access + 브라우저 다운로드 | 실제 PC의 결과 파일 존재 확인 | 사용자 `saveAs` + `chrome.downloads` 경로 |
| X-08 | Canva 원본 URL 관리 | 합법적·권한 내 열린 발표 탭 식별 및 반환 | W0 링크만 관리 |
| X-09 | Miricanvas 원본 URL 관리 | 상동 | W0 링크만 관리 |
| X-10 | `.ppt` 및 `.show` 오프라인 처리 | 라이선스에 맞는 로컬 파서/변환 수단과 실제 파일 로드 확인 | 미지원 알림 + 사용자가 직접 PPTX/PDF로 변환 |

**실험에 실물 샘플이 없으면 인위적 테스트 파일을 준비하고 부족한 실제 교사용 파일 검증을 문서에 명시**한다. 실험에 실패한 기능을 체크표시하여 출시하면 안 된다.

### 19.5 구현 단계(의존성 순서)

#### 단계 A — 확장·창·세션 뼈대

- [ ] TS/React/Vite 프로젝트를 만들고 Manifest V3 산출물을 빌드한다.
- [ ] Launcher, Player, Remote, Editor를 각각 독립 창으로 실행한다.
- [ ] 1화면과 2화면 배치, 지정/재지정, 디스플레이 해제 복구를 구현한다.
- [ ] 문서 ID·슬라이드 ID·개별 상태를 가진 `session-core`를 만든다.
- [ ] 모든 명령에 `sessionId/documentId/slideId/revision/commandId`를 포함하고 중복/늦은 메시지를 차단한다.
- [ ] 외부 앱 전환으로 Player를 닫거나 포커스 강제 회수하지 않는다.

**통과 기준:** 리모컨을 닫았다 다시 열어도 세션과 Player가 유지되고, 서로 다른 자료 ID의 상태가 섞이지 않는다.

#### 단계 B — PDF 완전 동작 수직 기능

- [ ] PDF.js에서 페이지 목록/썸네일/현재 페이지 렌더링 구현.
- [ ] PDF 2~3개를 동시에 열고 전환/복귀 시 각각의 마지막 페이지 기억.
- [ ] 현재 문서 종료 시 대기 화면, 비활성 문서 보존, 전체 종료 별도 구현.
- [ ] 시간 지정 자동 넘김과 정지/재개를 실제 경과 시간 기준으로 구현.
- [ ] Player에 주석 레이어 렌더링, Editor에 독립 슬라이드 선택 구현.
- [ ] 브라우저 IndexedDB에 작은 수정 델타 저장/복구, 슬라이드 캐시는 LRU 정책 사용.

**통과 기준:** PDF1 5페이지 → PDF2 2페이지 → PDF1 5페이지 복귀, Editor에서 PDF2 8쪽 수정 중 PDF1 화면 불변, 단일/듀얼 화면 작동.

#### 단계 C — 우클릭 빠른 수정·폰트·판서

- [ ] 현재 Player 및 비공개 Editor에서 우클릭 메뉴/터치 대체 조작.
- [ ] **단색에 한정**해 클릭 픽셀과 주변 대표 색상 선택지 제공; 같으면 후보 중복 숨김.
- [ ] 클릭 지점이 실제 검정 배경일 수 있으므로 색상을 강제로 보정하지 않고 선택권 유지.
- [ ] 검정 배경 선택 시 기본 흰 글씨, 그 외 기본 검정(대비 부족하면 변경 권고).
- [ ] 우클릭 메뉴 선택 후 **드래그로 고정 너비·높이**의 텍스트 상자 생성.
- [ ] 선택 폰트로 실제 측정한 텍스트 배치(너비, 높이, 줄바꿈)에 기반해 **제약 내 최대 글자 크기** 자동 탐색.
- [ ] 전역/개별 최소·최대 크기; 글자 크기 ± 수동 조정; 자동 맞춤 복귀.
- [ ] 조절점 대각선 드래그로 상자 크기 변경, 재계산; 이동·삭제·복제·undo/redo.
- [ ] 단순 판서/형광펜/가리개·화이트보드 MVP 구현.
- [ ] 동일한 논리 좌표를 Player와 Editor에서 사용해 표시 비율 불일치 제거.

**통과 기준:** 16:9/4:3 문서에서 글상자 위치 일치, 대각선 크기 변경 시 상자 고정+폰트 재계산, 검정색 후보 선택 시 흰 글씨, 원본 불변.

#### 단계 D — 미디어·노트·수업 도구

- [ ] 문서별 자동 넘김 간격, 슬라이드별 간격, 수동/자동/미디어 종료 후 넘김.
- [ ] 현재 활성 문서의 미디어만 지속 재생, 다른 문서로 전환하면 정책상 일시정지.
- [ ] 실제 시간 기반 타임라인과 브라우저 백그라운드 타이머 제한에 대한 재검증.
- [ ] 발표자 노트를 자료/슬라이드별 작성·확인하고 청중 화면에는 표시하지 않음.
- [ ] 수업 전체 타이머와 문서별 타이머의 범위를 분리.
- [ ] 발표 중 슬라이드와 교사 Editor의 대상 슬라이드가 서로 다른 상태임을 테스트.

**통과 기준:** 교사 PC에서 문서 편집·웹 탐색 중 5분 이상 발표의 지원 영상·오디오·자동 진행 중단 없음, Editor에서 다른 슬라이드 미리보기해도 Player 영상 일시정지 없음.

#### 단계 E — 정식 저장(로컬 PC 우선)

- [ ] 원본은 로컬 경로/파일 핸들로 참조하며 변경하지 않는다.
- [ ] 현재 슬라이드·글상자·판서·노트 등 **수정 델타만 IndexedDB에 임시 저장**한다.
- [ ] 버튼 선택 시 자료별 편집정보(가칭 `.wcp.json`)를 로컬 PC에 저장한다.
- [ ] 브라우저/OS에서 허용하는 방법으로 사용자 Downloads 폴더 또는 선택한 경로에 저장한다.
- [ ] PDF 수정본은 렌더링/합성 결과로 복사본 생성. 폰트 라이선스·한글 렌더링을 확인한다.
- [ ] PPTX는 지원 범위 내에서만 수정본 내보내기: 원본 슬라이드 유지에 실패하면 **화면 합성 기반 이미지 슬라이드 + 편집 가능한 추가 글상자** 대안을 안내한다. 효과/영상 손실 경고 필수.
- [ ] 일괄 종료 시 수정된 파일만 표시하고 여러 파일 선택 저장, 필요시 ZIP 묶음 구현.
- [ ] 다운로드 API 또는 파일 쓰기 실패 시 세션을 종료/삭제하지 않으며 재시도 기능 제공.
- [ ] 로컬 편집정보 파일을 불러올 때 원본 파일의 연결 확인. 원본이 이동되었으면 재선택을 요청한다.

**통과 기준:** 사용자가 지정한 로컬 PC 경로(또는 Downloads)에 실제 파일이 생성됨, 원본 해시 불변, 편집정보 재불러오기 가능, 저장 실패 시 변경사항 유지.

#### 단계 F — PPTX·웹 링크·한쇼·구형 PPT 단계적 통합

- [ ] 검증을 통과한 PPTX 렌더러를 Adapter 인터페이스에 연결하고 기능별 지원 배지 제공.
- [ ] PPTX에 내장된 음원·영상·시간 정보를 해석하는 기능은 지원 범위와 실패 사례를 문서화.
- [ ] Canva/미리캔버스 URL은 W0로 실행, 출처별 최소 권한을 요청한다.
- [ ] W1~W3(오버레이/페이지 인식/리모컨 원격 이동)은 **원본 사이트 구조와 정책·권한 내**에서 실제 검증한 것만 켠다.
- [ ] `.ppt`·`.show`는 실제 렌더러/로컬 변환 경로가 검증되지 않았으면 '추가 변환 필요'로 명확히 안내한다.
- [ ] 브라우저 페이지와 로컬 PPTX가 공존해도 중앙 리모컨에서 자료 전환은 가능하게 한다.

**통과 기준:** 모든 콘텐츠 항목을 세션에 등록할 수 있으며, 미지원 기능을 작동하는 것처럼 가장하지 않고 안전하게 안내한다.

### 19.6 데이터 모델 및 명령 계약(최소 스키마)

```ts
type SourceType = 'pdf' | 'pptx' | 'ppt' | 'show' | 'canva' | 'miricanvas';
type AdapterCapability =
  | 'open' | 'page-count' | 'current-page' | 'goto-page' | 'thumbnails'
  | 'embedded-media' | 'effects' | 'overlay' | 'private-preview' | 'export';

type PresentationRef = {
  id: string; type: SourceType; title: string;
  fileHandleKey?: string; url?: string; fileFingerprint?: string;
};

type SessionData = {
  schemaVersion: 1; sessionId: string; title: string;
  documentOrder: string[]; presentedDocId: string | null;
  presentedSlideId: string | null;
  editorSelection: { docId: string; slideId: string } | null;
  documents: Record<string, {
    source: PresentationRef; lastSlideId: string | null;
    knownSlideCount?: number;
    capability: AdapterCapability[];
    overlaysBySlide: Record<string, OverlayData[]>;
    notesBySlide: Record<string, string>;
    autoplayBySlide: Record<string, { mode: 'manual' | 'seconds' | 'media-end'; seconds?: number }>;
    mediaBookmark?: { slideId: string; timeSec: number; paused: boolean };
    dirty: boolean;
  }>;
  globalTimer?: { startedAt: number; durationSec: number; pausedAt?: number };
  lastSavedToLocalAt?: number;
  updatedAt: number;
};

type OverlayData = {
  id: string; kind: 'textbox' | 'stroke' | 'mask' | 'shape';
  // 0..1 정규화 좌표. 표시창 픽셀/해상도에 종속되지 않는다.
  rect: { x: number; y: number; w: number; h: number };
  text?: string; bgColor?: string; color?: string;
  fontFamily?: string; fontMinPx?: number; fontMaxPx?: number;
  fontMode?: 'auto-max' | 'manual'; manualFontPx?: number;
  align?: 'left' | 'center' | 'right';
  valign?: 'top' | 'middle' | 'bottom';
  zIndex: number;
};

type PresenterCommand =
  | { type: 'ACTIVATE_DOCUMENT'; sessionId: string; documentId: string; commandId: string }
  | { type: 'GOTO_SLIDE'; sessionId: string; documentId: string; slideId: string; commandId: string }
  | { type: 'PAUSE'; sessionId: string; documentId: string; commandId: string }
  | { type: 'RESUME'; sessionId: string; documentId: string; commandId: string }
  | { type: 'UPSERT_OVERLAY'; sessionId: string; documentId: string; slideId: string; overlay: OverlayData; commandId: string }
  | { type: 'CLOSE_DOCUMENT'; sessionId: string; documentId: string; commandId: string }
  | { type: 'CLOSE_ALL'; sessionId: string; commandId: string };
```

- 이 스키마는 **시작 계약**이며 구현 도중 마이그레이션 가능하다. `schemaVersion`은 반드시 저장한다.
- 외부 링크의 슬라이드 번호가 확인되지 않는 경우 `null/unknown`을 허용한다. 임의의 현재 번호나 슬라이드 개수를 만들어 넣지 않는다.
- UI 상태와 저장 모델을 혼합하지 않는다. 저장할 데이터의 JSON 직렬화 여부/파일 핸들의 별도 보관 여부를 분리한다.
- 글상자의 회전 등 초기 미지원 속성은 UI에서 만들지 않는다. 지원 범위가 합의되면 스키마를 확장한다.

### 19.7 글씨 자동 맞춤 알고리즘 요구

1. 사용자 드래그로 만든 `rect`의 너비·높이와 안쪽 여백을 계산한다.
2. 최소·최대 폰트 크기, 실제 선택된 로컬/내장 글꼴, 줄바꿈, 정렬 및 줄 간격을 입력으로 받는다.
3. 실제 텍스트 배치 결과를 측정하는 함수 `fits(fontSize)`를 만든다. 가로·세로 **둘 다** 만족해야 참이다.
4. `min..max` 범위에 대해 이진 탐색 또는 그에 준하는 정밀 탐색으로 들어갈 수 있는 **가장 큰** 글씨 크기를 선택한다.
5. 내용이 최소 크기로도 맞지 않으면 최소값보다 더 작게 자동 축소하지 않고 경고한다. 글상자를 늘리거나 내용을 축약하도록 안내한다.
6. `+/-` 버튼을 누르면 `manual` 모드가 되며, `auto` 버튼으로 최대 글씨 맞춤에 복귀한다. 수동 확대로 오버플로가 생기면 사용자에게 표시한다.
7. 한글 IME 조합 중에는 매 조합 키 입력마다 급격하게 흔들리지 않게 `compositionstart/end`와 필요시 디바운스 처리를 고려한다.
8. 16:9/4:3/세로 PDF 등에서 동일한 슬라이드 논리 좌표를 사용한다.

### 19.8 저장·내보내기 상세 계약

```text
원본 PC 파일(x.pptx, x.pdf)  ──읽기──> Player/Editor
                                     │
                              빠른 수정 델타(글상자/판서/노트/설정)
                                     │
                         IndexedDB에 임시 복구만 수행
                                     │
                             [사용자 저장/종료 선택]
                               ┌────────────┴────────────┐
                               ▼                         ▼
                x_편집정보.wcp.json (PC 파일)    x_수정본.pdf / .pptx (PC 파일)
                     재편집을 위한 원본 참조      타 프로그램 사용/공유용 복사본
```

- **권장 UX 기본값:** 현재 자료 종료 시 변경이 있으면 `편집정보를 PC에 저장`을 우선 선택해 둔다. `수정본 파일도 저장`은 추가 체크 옵션으로 한다. 아무 저장도 하지 않고 종료하려면 별도 확인을 한다.
- **편집정보 파일에는 원본 바이트를 기본 포함하지 않는다.** 내용은 `schemaVersion`, source filename/metadata/fingerprint(필요 시), 오버레이, 노트, 발표 설정 등으로 구성한다.
- **원본 재연결:** 파일 핸들 권한 만료/이동/수정이 발생하면 경로를 추측해 임의 파일을 연결하지 않는다. 사용자에게 재선택을 요청하고 파일 이름·크기·해시 등으로 일치 여부 확인 후 연결한다.
- **PDF 결과물 복사본:** 페이지 렌더/벡터 오버레이 합성 가운데 우선 기술을 선정해 로컬 PDF를 생성한다. 미디어·수업 전체 타이머는 PDF 결과물에 들어갈 수 없음을 안내한다.
- **PPTX 결과물 복사본:** 가능한 경우 원본 슬라이드의 기존 구조를 유지하고 새로운 도형을 추가한다. 원본 레이아웃·미디어 호환성 보존에 실패하면 **사용자에게 명확히 알리고** 이미지 기반 슬라이드 대안을 제공한다. 기존 PPTX 원본과 완벽하게 일치한다고 표기하지 않는다.
- **다중 파일:** '현재 자료 저장/종료'와 '모두 저장/종료'는 별도 메뉴이다. 일괄 저장은 각각의 복사본 또는 ZIP 아카이브를 PC에 내려받는다.
- **저장 완료 판정:** 파일 생성 성공, 실제 다운로드 완료/실패 이벤트 확인, 오류 문구 및 재시도 제공. 완료 확인 전에 수정정보 메모리/IndexedDB를 제거하지 않는다.
- **브라우저 설정/임시 상태:** 작은 기본설정은 `chrome.storage.local`; 변경 델타는 IndexedDB; 썸네일·임시 미디어 캐시처럼 큰 바이너리는 한도가 있는 OPFS. 단 OPFS는 절대 로컬 PC의 정식 파일 백업을 대체하지 않는다.
- `chrome.downloads`의 `filename`은 **Downloads 기준 상대 경로**이지 임의의 절대경로가 아니다. 사용자가 저장 위치를 고를 때는 `saveAs` 또는 사용자 승인 File System Access API를 이용한다.
- 내보내기 문서의 폰트 포함은 **개별 폰트 라이선스**에 따른다. 확장 패키지에 내장한 폰트를 사용자에게 무단 배포하거나 다운로드 파일에 강제 포함하지 않는다.

### 19.9 포커스 독립 재생의 구체적 시험 정의

**지원 대상:** 자체 Player가 렌더링하고 있는 PDF/PPTX의 지원된 미디어·슬라이드 전환 기능. Canva/미리캔버스 원본 웹사이트 재생은 사이트별 지원 수준에 따름.

- Player가 모니터 2에 표시되고 모니터 1의 다른 브라우저 탭/문서 작성기/메신저가 활성화되는 동안 Player의 `visibilityState`, `focus`, 미디어 `currentTime`, `playing/paused/ended` 이벤트, 다음 슬라이드 예상/실제 시점을 기록한다.
- 5분 이상 포커스를 다른 앱으로 옮긴 상태에서 지원되는 영상·오디오가 계속 진행되는지 비교한다.
- 타임라인은 `deadline = startTimestamp + duration`처럼 **절대 경과 시간**을 기준으로 정의한다. 느린 이벤트 루프가 누적 지연을 일으키지 않도록 하고, 일시정지·복귀·전환 시 deadline을 다시 계산한다.
- 첫 오디오 자동재생은 브라우저 정책의 영향을 받으므로 **사용자의 명시적 발표 시작** 동작을 통해 재생을 초기화하고, `play()` 실패는 UI에 원인·재시도 버튼으로 표시한다.
- 발표 화면 자체가 가려지거나 최소화되는 경우는 다른 상황이다. 해당 경우의 프레임/애니메이션 정책은 별도 테스트하고 지원 가능 범위만 표기한다.
- 다른 문서로 전환하는 경우 이전 문서의 미디어 정지는 **의도된 일시정지 정책**이므로 포커스 독립 재생 실패로 취급하지 않는다.

### 19.10 웹 링크 어댑터 역량 구분

| 수준 | 할 일 | 출시 표기 |
|---|---|---|
| W0 (기본) | Canva/미리캔버스 URL 등록·유효성 검사·권한 안내·관리형 탭/창 실행·재진입 | 검증된 링크 실행 |
| W1 (실험) | 페이지 위에 독립 오버레이/도구 레이어를 허용된 방식으로 주입 | 검증된 사이트/화면에서만 켬 |
| W2 (실험) | 실제 현재 페이지 수·번호·리모컨 이동·진행 위치 저장 및 복원 | 사이트별로 가능 여부 체크 |
| W3 (장기) | 발표 중이지 않은 다른 온라인 슬라이드의 비공개 미리보기·편집 | 공식 제공 데이터/허용된 연동 때만 |

- 원본 사이트가 로그인·공유 권한·iframe/전체화면 제한을 가진다면 이를 우회하지 않는다.
- DOM 구조를 추측한 코드를 기본 운영 경로로 강제하지 않는다. 변동 취약 지점은 adapter로 격리한다.
- Canva의 페이지 목록 API는 공식 **preview API**로 공용 배포 앱에서 제약을 명시하고 있으므로 기본 기능의 필수 구성 요소로 사용하지 않는다.
- 외부 웹사이트의 미디어/애니메이션이 포커스 상실 후 멈출 경우 **확장 프로그램으로 언제나 해결 가능하다고 보장하지 않는다**. 원본 사이트 재생을 존중하고 지원 상태를 표시한다.
- 웹 발표를 원본으로 사용한 경우에도 수업 세트의 링크, 교사 노트, 별도 편집 데이터는 로컬 저장할 수 있다. 실제 원본 캔바/미리캔버스 문서를 자동 편집·저장한다고 주장하지 않는다.

### 19.11 보안·성능·접근성

- MV3 최소 권한. `storage`/`downloads`/`system.display`/`scripting` 등은 실제로 필요한 기능이 구현될 때 선언하며, 외부 페이지 host 권한은 Canva·미리캔버스 도메인별로 선택적으로 요청한다. `all_urls` 기본 요구 금지.
- 악성/손상된 문서에 대한 파일 크기·페이지 수·압축 폭탄 방지, HTML/문자열 주입 방지, XML 외부 엔터티 위험, ZIP 파싱 오류를 처리한다. 가져온 노트/텍스트를 임의 HTML로 삽입하지 않는다.
- 사용자의 PDF/PPTX·판서·노트·링크 주소를 우리 서버에 보내지 않는다. 분석/텔레메트리도 명시적 허락 없이 사용하지 않는다.
- 캐시 용량 상한·최근 사용 순 정리·원본과 캐시 크기/용량 확인 UI를 제공한다. 큰 PPTX 안의 동영상을 원본 그대로 두 번 저장하지 않는다.
- 터치 사용자는 길게 누르기 또는 별도 '빠른 수정' 도구 버튼으로 같은 기능에 접근 가능해야 한다. 키보드 단축키와 충분한 버튼 크기 제공.
- 폰트는 배포 라이선스가 허용된 내장 글꼴 + 로컬 글꼴(권한 필요한 경우 명시적 요청) + 사용자가 직접 선택한 파일을 지원한다. 다운로드 산출물에 글꼴을 무조건 포함하지 않는다.
- 단일 모니터 또는 복제 모드에서 학생에게 교사용 노트가 노출될 수 있으므로, 리모컨·편집창의 노출 위험을 사용자에게 명확히 알린다.
- Windows에서 먼저 검증하고, OS 차이·멀티 디스플레이 DPI 스케일/포커스 정책은 호환성 매트릭스로 관리한다.

### 19.13 개발 에이전트가 각 단계 완료 후 보고할 내용

```text
[단계명]
- 구현한 기능 (실제로 작동하는 것만):
- 수정/추가된 주요 파일:
- 빌드 결과:
- 자동 테스트 통과/실패:
- 웨일 실기기 테스트 완료 여부 (완료/미실시/실패):
- 지원되지 않거나 제한된 기능:
- 현재 미해결 이슈 및 재현 절차:
- 다음 단계 작업:
```

- 사용자가 로컬 AI에 개발을 맡길 때, 에이전트는 **현재 단계의 코드를 만들고 검증한 후** 다음 단계로 진행한다.
- 위 보고 항목이 없으면 단지 파일이 존재한다는 이유로 기능이 완성되었다고 판단하지 않는다.
- 실제 브라우저/운영체제의 권한 승인이 필요한 경우, 사용자의 허가가 필요한 순간에만 요청한다. 무단으로 개인 파일을 수집하거나 외부로 업로드하지 않는다.
- 개발에 필요한 내부 기술 선택은 권장 기본안을 사용해 진행하고, 사용자의 요구사항을 바꾸는 결정(서버 도입, 원본 덮어쓰기, 외부 계정 필수화, 유료 엔진 채택 등)만 별도로 동의받는다.

### 19.14 로컬 AI 코딩 세션 첫 입력 문구(복사해서 사용)

> 첨부한 `웨일_통합_프레젠테이션_확장프로그램_개발_착수지시서_v4.0.md`를 이번 프로젝트의 최상위 개발 기준으로 삼아라. 먼저 문서를 모두 읽고, 기존 저장소가 있다면 현재 상태를 확인한 뒤 구현 계획을 단계별로 세우고 즉시 작업을 시작하라. 필수 사전 선택은 문서에서 확정했으므로 반복 질문하지 마라. 초기 단계에서는 Windows용 네이버 웨일 Manifest V3 확장 프로그램을 TypeScript/React/Vite로 구성한다. 서버·회원가입·ONLYOFFICE 의존성 없이 로컬 우선으로 구현한다. 먼저 확장 런처·독립 Player/Remote/Editor·PDF 다중 자료 전환·상태 복원·우클릭 글상자·자동 글씨 최대 맞춤·로컬 편집정보 내보내기까지 작동하는 수직 MVP를 완성하라. PPTX·한쇼·구형 PPT·캔바·미리캔버스는 기술 검증과 어댑터로 별도 관리하고, 검증하지 않은 호환성을 완료했다고 주장하지 마라. 교사가 다른 프로그램을 조작하더라도 발표 창의 지원 미디어와 자동 넘김이 멈추지 않는 것을 P0 품질 조건으로 삼아라. 원본 파일을 절대로 덮어쓰지 말고 다운로드 결과는 실제 PC 파일로 남겨라. 단계별로 빌드·테스트를 실행하고 검증 결과를 기록하며, 가능한 한 실제 코드를 구현하라.

## 21. 최종 설계 결정과 범위 문구

**프로그램의 본질은 ‘브라우저 툴바에서 빠르게 실행하는, 여러 로컬 파일과 온라인 발표를 하나의 교사용 리모컨으로 통합 관리하는 로컬 우선 수업 프레젠테이션 시스템’이다.** 사용자는 PDF/PPTX·한쇼 또는 캔바·미리캔버스 링크를 등록하고, 화면에서 발표되는 자료를 교사용 창으로 제어한다. 다른 앱을 조작하더라도 자체 Player의 지원되는 미디어·효과·자동 넘김은 포커스 때문에 멈추지 않도록 한다.

빠른 수정의 대상은 원본 편집이 아닌 **단색 맞춤 배경의 글상자와 판서 레이어**이며, 현재 보여주는 슬라이드뿐 아니라 비공개 미리보기에서 다른 파일의 다른 슬라이드도 편집할 수 있다. 원본은 PC에 보존하고 수정 레이어만 브라우저에 임시 저장하며, 종료 시 **현재 자료만 종료**를 기본으로, **모두 종료**를 별도로 제공한다. 저장 요청 시 편집정보와 완성된 수정본은 **로컬 PC에 새 파일(복사본)**로 내보낸다.

기술적 미확정 영역—PPTX의 일부 고급 효과/미디어, `.ppt`/`.show` 직접 열기, 캔바·미리캔버스 내부 슬라이드 통합 제어—은 기술 실험을 통해 기능별로 지원 수준을 확정한다. 이를 처리하기 위한 자체 서버, Microsoft/ONLYOFFICE 엔진 무단 이식, 로그인 의무화는 이번 설계에 포함하지 않는다.

## 22. 최종 결론

개발 중심은 **범용 오피스 편집기 제작**이 아니라 **웨일 확장 프로그램을 거쳐 시작하는 모든 수업 발표의 일관된 운영 경험**이다. PDF·PPTX를 기반으로, 추후 한쇼와 구형 PPT, 캔바·미리캔버스 발표 링크를 같은 세션에 등록하고 교사용 리모컨·편집창에서 제어한다.

그중 초기 구현에서 최우선은 **(1) 포커스 독립 재생, (2) 여러 자료의 마지막 페이지 및 상태 기억, (3) 발표 화면과 비공개 미리보기 편집의 분리, (4) 드래그 고정 글상자와 최대 글씨 크기 자동 맞춤, (5) 개별·일괄 종료와 원본 보존형 복사본 저장**이다.

**기획 확정과 기술 구현 완료는 구분한다.** 특히 PPTX 고급 효과, 한쇼 원본 재생, 외부 웹사이트 내부 제어는 별도 기술 실험을 통과한 범위에서만 지원한다고 표현한다. 이것이 설치와 조작이 간단하면서 실제 수업에서 신뢰할 수 있는 확장 프로그램을 만드는 가장 현실적인 접근이다.
