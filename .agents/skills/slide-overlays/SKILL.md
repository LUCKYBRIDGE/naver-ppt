# 빠른 수정 레이어

[PRD v5](../../../naver-ppt_PRD_v5.md) §13/28과 [데이터 계약](../../../docs/DATA_CONTRACTS.md)을 우선한다. v4 [§6 및 §19.7](../../../docs/source/spec-v4.md)은 충돌하지 않는 상세 구현 참고다. Editor draft는 명시적 commit 전까지 Player에 노출하지 않는다.

- Player와 Editor 모두 우클릭/길게 누르기/도구 버튼으로 접근한다. 클릭 실제 픽셀과 주변 대표 단색을 선택지로 제공하며 같은 후보는 합친다.
- 원본 렌더와 이미 추가된 레이어를 분리해 샘플링한다. 검정 클릭을 오류로 간주해 강제 주변색으로 바꾸지 않는다. 검정 배경 기본 글자는 흰색, 일반 배경은 검정색이며 사용자가 변경할 수 있다.
- 사용자가 먼저 드래그한 rect를 고정한다. 실제 로드된 폰트의 폭·줄바꿈·행 높이·여백·행간으로 가로/세로 모두 맞는 최대 크기를 찾는다. 글자 수 추정만으로 맞춤을 확정하지 않는다.
- 최소 크기도 맞지 않으면 overflow 결과와 경고를 반환하고 텍스트를 숨기거나 최소 이하로 축소하지 않는다. 수동 ±는 manual, 자동 버튼은 auto-max 복귀다.
- 한글 조합 중 draft와 최종 계산을 구분하고 composition 완료 때 안정적으로 확정한다. Player/Editor/export의 폰트 파일과 기준 viewport를 일치시킨다.
- 내부 클릭=문자 편집, 테두리=이동, 모서리=크기 조절. 정규화 좌표·z-index·표시/숨김·undo/redo를 저장한다. 여러 화면 비율에 표시 픽셀을 그대로 저장하지 않는다.
- 판서/마스크는 글상자와 별도 종류로 관리한다. 가져온 문자열은 텍스트로 렌더링한다.

실제 글씨 맞춤 구현에는 단위 테스트가 필수다. 실제 브라우저 폰트 측정 검증을 함께 마련하고 16:9/4:3/세로, 좁은 상자, 긴 한글, 줄바꿈, 최소 제한, 수동 overflow, 모서리 재계산을 시험한다. 모킹 fits 함수 결과만으로 실제 글꼴 품질을 완료라 하지 않는다.
