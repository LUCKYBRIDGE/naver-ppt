# 렌더러와 웹 서비스 검증

[TECH_SPIKES.md](../../../docs/TECH_SPIKES.md), [COMPATIBILITY_MATRIX.md](../../../docs/COMPATIBILITY_MATRIX.md), [LICENSES.md](../../../docs/LICENSES.md)의 관련 항목을 읽는다. 실험 목표와 실제 지원 수준을 구분한다.

- PDF를 첫 수직 기능으로 완성한다. PDF.js를 우선 실험하고 패키지 worker/폰트/WASM 경로·오프라인·배포 크기·원본 보존을 확인한다.
- PPTX 렌더러는 2종 이상 비교한다. 실제 교사용 10종 이상에서 텍스트/사진/표/영상/음원/노트/효과/폰트 차이를 기록한다. 후보 이름만으로 원본 수준 재현을 보장하지 않는다.
- PPT/SHOW는 설치 없는 로컬 파서/변환 경로와 라이선스·오프라인·외부 프로그램 조건을 확인한다. 경로 미확정이면 변환 필요를 알리고 PDF 핵심 개발을 계속한다.
- 웹은 W0 링크/창 관리부터. W1 표시 보조, W2 실제 페이지/제어, W3 비공개 미리보기는 각각 공식 수단·사이트 정책·권한·DOM/iframe/전체화면 제약을 시험한 뒤 활성화한다.
- 페이지 수/위치가 미확인인 웹 자료는 null이다. 가짜 번호/썸네일·원본 서비스 자동 편집/저장·강제 재생 지속을 주장하지 않는다.
- `open`, `goto-page`, `overlay`, `private-preview`, `embedded-media`, `export` 등을 기능별 판정한다. `supported/partial`은 샘플·환경·시험 근거와 제한을 가진다.
- 새 의존성을 선정하기 전에 서버 필요/계정/유료/원격 코드/오프라인/재배포를 확인한다. 자체 서버·ONLYOFFICE 런타임으로 확정 제약을 우회하지 않는다.

현재 인터넷 기술 정보를 사용할 때는 공식 문서와 공개 소스의 최신 근거를 확인한다. 결과물은 실험표, 후보 비교, 기능별 역량, 실패 대안, 환경/샘플/일자와 재현 절차다. 미실시 항목은 unverified로 남긴다.
